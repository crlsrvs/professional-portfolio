Actúa como un Senior Frontend Engineer y UI/UX Designer especializado en portafolios profesionales para desarrolladores de software.

## Objetivo

Crea una página web personal para presentar mi experiencia profesional como Software Engineer. La utilizaré como referencia en postulaciones laborales y la publicaré mediante GitHub Pages.

No quiero un portafolio genérico ni una plantilla típica de desarrollador. Quiero una página elegante, moderna, minimalista y profesional, que transmita experiencia trabajando en productos reales y aplicaciones empresariales.

## Stack técnico

- React + TypeScript + Vite.
    
- CSS moderno, con libertad para elegir Tailwind CSS si aporta valor.
    
- Diseño responsive y mobile-first.
    
- Componentes reutilizables.
    
- Código limpio, mantenible y bien organizado.
    
- GitHub Actions para desplegar automáticamente en GitHub Pages.
    

Antes de comenzar, inspecciona el repositorio y aprovecha cualquier configuración existente. No sobrescribas trabajo previo innecesariamente.

Soy Software Engineer especializado en desarrollo frontend, con experiencia en aplicaciones empresariales y soluciones fullstack.

## Estructura de la página

1. **Hero:** presentación breve y contundente como Software Engineer, con énfasis en React, TypeScript y desarrollo de aplicaciones empresariales. Incluye botones para LinkedIn, GitHub y contacto.
    
2. **About:** resumen profesional centrado en experiencia, resolución de problemas y colaboración en equipos de ingeniería.
    
3. **Selected Professional Work:** sección visualmente atractiva con tarjetas que describan proyectos, funcionalidades desarrolladas, tecnologías y contribuciones. No presentes sitios corporativos como proyectos personales.
    
4. **Technical Skills:** tecnologías organizadas por categorías, sin porcentajes de dominio ni niveles inventados.
    
5. **Professional Work & Confidentiality:** una nota breve y natural explicando que varios proyectos son aplicaciones internas o productos comerciales, por lo que su código fuente y algunos entornos de producción no son públicos. Ofrece profundizar en la experiencia durante una entrevista.
    
6. **Contact:** enlaces a perfiles profesionales y correo electrónico.
    

## Diseño

- Estética premium, similar a páginas personales de ingenieros de empresas tecnológicas.
    
- Tipografía moderna, excelente jerarquía visual y espacios bien distribuidos.
    
- Paleta sobria con un color de acento.
    
- Animaciones sutiles, respetando `prefers-reduced-motion`.
    
- Buen contraste y accesibilidad.
    
- Evita barras de habilidades, efectos exagerados, fotografías de stock, estadísticas inventadas y textos genéricos.
    
- Prioriza la experiencia móvil tanto como desktop.
    

El contenido debe estar inicialmente en **inglés**, con redacción profesional, natural y concisa, apropiada para reclutadores internacionales.

## Requisitos técnicos

- SEO básico mediante metadatos, Open Graph y etiquetas semánticas.
    
- Buen rendimiento y prácticas orientadas a Core Web Vitals.
    
- Evitar dependencias innecesarias.
    
- Soporte para el `base path` de GitHub Pages.
    
- Workflow de GitHub Actions para build y deploy.
    
- README con instrucciones para desarrollo local, personalización y publicación.
    
- Centralizar el contenido editable (experiencias, tecnologías, enlaces y datos personales) en un archivo de configuración.
    
- Utilizar placeholders claramente identificados para información personal que no esté disponible.
    
- No inventar fechas, métricas, responsabilidades, enlaces ni resultados.
    

## Forma de trabajo

1. Inspecciona el repositorio.
    
2. Define una estructura sencilla y escalable.
    
3. Implementa la página completa con contenido profesional basado en la información proporcionada.
    
4. Configura el despliegue a GitHub Pages.
    
5. Ejecuta las verificaciones disponibles: TypeScript, lint y build.
    
6. Corrige los errores encontrados.
    
7. Resume los archivos creados y los pasos manuales necesarios para publicar.
    

Toma decisiones técnicas razonables sin solicitar confirmación por detalles menores.
